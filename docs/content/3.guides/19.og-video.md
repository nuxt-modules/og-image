Messages on iOS and macOS plays an MP4 `og:video` inline and loops it in the link bubble. Set `video` and the module renders your Takumi template's CSS animations to an MP4 at the same URL as the image, with an `.mp4` extension.

```vue [pages/invite/[code\\].vue]
<script lang="ts" setup>
const code = String(useRoute().params.code)

useSeoMeta({ title: `Join Beaver · Invite code: ${code}` })

defineOgImage('Invite.takumi', { code }, { video: { durationMs: 2000, fps: 30 } })
</script>
```

```vue [components/OgImage/Invite.takumi.vue]
<template>
  <div class="h-full w-full flex items-center justify-between bg-black px-24">
    <p class="text-9xl font-bold text-white">
      {{ code }}
    </p>
    <div class="w-56 h-56 rounded-3xl bg-amber-400 animate-spin" />
  </div>
</template>
```

The page gets both renditions:

```html
<meta property="og:image" content="https://example.com/_og/s/o_98b47b78dd1cefbb.png">
<meta property="og:video" content="https://example.com/_og/s/o_98b47b78dd1cefbb.mp4">
<meta property="og:video:type" content="video/mp4">
```

Discord plays the video once, with player controls. Clients that don't play `og:video`, such as Slack, X, LinkedIn and WhatsApp, show `og:image`.

## Animations

Takumi samples CSS animations at each frame. Use a Tailwind `animate-*` utility such as `animate-spin`, an inline `animation` style, or pass your own keyframes through `takumi.css`:

```ts
defineOgImage('Invite.takumi', { code }, {
  video: true,
  takumi: {
    css: [{ keyframes: 'float', steps: [
      { offset: 'from', style: { transform: 'translateY(0)' } },
      { offset: 'to', style: { transform: 'translateY(-24px)' } },
    ] }],
  },
})
```

`takumi.timeMs` picks the point on the timeline used for the still `og:image`.

## Requirements

- The Takumi renderer. With another renderer, the page gets no `og:video` and dev mode logs a warning.
- An `ffmpeg` binary on the server, or at build time when the page is prerendered. Set `NUXT_OG_IMAGE_FFMPEG` to use one that isn't on `PATH`. Edge runtimes can't spawn FFmpeg, so prerender these pages there. If `ffmpeg` is missing, the prerender fails the build.
- `durationMs` is capped at 10 seconds and `fps` at 60. Messages caps a preview's media at 10 MB. A 2 second 1200x600 clip at 30 fps encodes to about 95 KB.
- The [render timeout](/docs/og-image/guides/security) (`security.renderTimeout`, 15 seconds by default) covers every frame and the encode.
- [URL signing](/docs/og-image/guides/security#url-signing) for videos rendered at runtime. Signing is on by default. Without it, a request could add `video` to any image URL, so with `security.secret: false` the `.mp4` URL answers `403` and only prerendered videos work.

The `.mp4` URL answers `400` for an image without `video`. The `og:video` tag comes from the server HTML, which is what link previews read. After client-side navigation, the page head carries `og:image` only.
