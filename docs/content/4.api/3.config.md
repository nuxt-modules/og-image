Configure all options on this page under the `ogImage` key in your Nuxt config.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    // options below go here, e.g.
    defaults: {
      extension: 'png',
    },
  },
})
```

### `enabled`

- Type: `boolean`{lang="ts"}
- Default: `true`{lang="ts"}

Conditionally toggle the module.

### `defaults`

- Type: `OgImageOptions`{lang="ts"}
- Default: `{ width: 1200, height: 600, extension: 'png', emojis: 'noto', cacheMaxAgeSeconds: 60 * 60 * 24 * 3 }`{lang="ts"}

The default options to use when generating images.

See the [defineOgImage](/docs/og-image/api/define-og-image) documentation for more details.

### `compatibility`

- Type: `{ dev?: CompatibilityFlags, runtime?: CompatibilityFlags, prerender?: CompatibilityFlags }`{lang="ts"}
- Default: `{}`{lang="ts"}

Override the compatibility flags.

See the [Renderers](/docs/og-image/renderers) guide to learn more.

### `zeroRuntime`

- Type: `boolean`{lang="ts"}
- Default: `false`

Enable zero runtime mode. See the [Zero Runtime](/docs/og-image/guides/zero-runtime) documentation for more details.

### `satoriOptions`

- Type: `SatoriOptions`{lang="ts"}
- Default: `{}`{lang="ts"}

Options to pass to Satori when generating images. See the [Satori docs](https://github.com/vercel/satori).

### `resvgOptions`

- Type: `ResvgRenderOptions`{lang="ts"}
- Default: `{}`{lang="ts"}

Options to pass to Resvg when generating images. See the [Resvg docs](https://github.com/yisibl/resvg-js).

### `sharpOptions`

- Type: `SharpOptions | true`{lang="ts"}
- Default: `undefined`{lang="ts"}

Options to pass to Sharp when generating images. See the [Sharp docs](https://sharp.pixelplumbing.com/).

### `cacheVersion`

- Type: `string | false`{lang="ts"}
- Default: module version

Custom version string for cache key namespacing.

By default, the module uses its version number, which invalidates the cache on module upgrades. Set a static value like `'v1'` to persist the cache across module updates. Set to `false` to disable versioning entirely.

### `fontSubsets`

- Type: `string[]`{lang="ts"}
- Default: `['latin']`{lang="ts"}

Font subsets to download when resolving missing font families via `fontless`.

This option only controls which subsets the module downloads when supplementing missing families for the [Satori](/docs/og-image/renderers/satori) renderer. Fonts from `@nuxt/fonts` always include all their available subsets.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    fontSubsets: ['latin', 'devanagari', 'cyrillic']
  }
})
```

### `componentDirs`

- Type: `string[]`{lang="ts"}
- Default: `['OgImage', 'OgImageCommunity', 'og-image', 'OgImageTemplate']`{lang="ts"}

Extra component directories the module should use to resolve components.

### `runtimeCacheStorage`

- Type: `boolean | string | (Record<string, any> & { driver: string })`{lang="ts"}
- Default: `true`{lang="ts"}

Modify the runtime cache behavior.

Passing `false` disables runtime image storage. Passing `true` uses configured Nitro cache storage when available.
Otherwise, the module uses a memory cache with a 64 MiB entry limit. Evicted images render again on request.

The limit does not cap total server memory. Explicit storage settings must provide their own limit or expiry.

To configure a storage driver directly, pass an object with its driver name and options.

See the [Runtime Cache guide](/docs/og-image/guides/runtime-cache) for storage limits and persistent drivers.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    runtimeCacheStorage: {
      driver: 'redis',
      host: 'localhost',
      port: 6379,
      password: 'password'
    }
  }
})
```

### `buildCache`

- Type: `boolean | { base?: string }`{lang="ts"}
- Default: `false`{lang="ts"}

Enable persistent build cache for CI environments. Caches rendered images to disk so they persist between CI runs.

The cache key includes the options hash, component template hash, and module version, ensuring automatic invalidation when any of these change.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    buildCache: true
    // or with custom directory:
    // buildCache: { base: '.cache/og-image' }
  }
})
```

Default cache directory: `node_modules/.cache/nuxt-seo/og-image/`

See the [Build Cache guide](/docs/og-image/guides/build-cache) for CI configuration examples.

### `publish`

- Type: `{ storage: string, baseURL: string }`{lang="ts"}
- Default: disabled

Upload rendered images to public object storage through a Nitro storage mount.
After upload, prerendered `og:image` and `twitter:image` tags use the public URL.

Runtime pages use the app image URL until an image request publishes the image.
Later SSR pages use the public URL while its manifest is fresh.

If the manifest expires or the object disappears, pages return to the app URL.
The next image request can publish the image again.

For S3-compatible endpoints, use Nitro's `s3` driver and install `aws4fetch`: `pnpm add aws4fetch`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    publish: {
      storage: 'og-image-public',
      baseURL: 'https://files.example.com/og'
    }
  },
  nitro: {
    storage: {
      'og-image-public': {
        driver: 's3',
        endpoint: process.env.OG_STORAGE_ENDPOINT,
        bucket: process.env.OG_STORAGE_BUCKET,
        region: process.env.OG_STORAGE_REGION,
        accessKeyId: process.env.OG_STORAGE_ACCESS_KEY,
        secretAccessKey: process.env.OG_STORAGE_SECRET_KEY
      }
    }
  }
})
```

The mount must support raw writes.
During prerendering, Node must be able to access it.
The public URL must serve the mount's keys, including any driver prefix.

#### Cloudflare R2

Use Nitro's `cloudflare-r2-binding` driver for runtime publishing inside Workers.
Prerender builds need an S3-compatible mount to access the same bucket.
Use the same storage mount name for both configurations.

For R2, use `devStorage` for build-time S3 access and `storage` for the Worker binding:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    publish: { storage: 'og-image-public', baseURL: 'https://files.example.com/og' }
  },
  nitro: {
    storage: {
      'og-image-public': { driver: 'cloudflare-r2-binding', binding: 'OG_IMAGES' }
    },
    devStorage: {
      'og-image-public': {
        driver: 's3',
        endpoint: process.env.R2_ENDPOINT,
        bucket: process.env.R2_BUCKET,
        region: 'auto',
        accessKeyId: process.env.R2_ACCESS_KEY,
        secretAccessKey: process.env.R2_SECRET_KEY
      }
    }
  }
})
```

The S3 endpoint uses your account's `r2.cloudflarestorage.com` host.
Add the `OG_IMAGES` binding to your Cloudflare deployment configuration.

#### Manifest expiry

Each image has a manifest with its object key and expiry time.
The manifest key includes the site origin, image options, the component template hash, and `cacheVersion`.
Signed and unsigned requests share the same manifest key.

Builds reuse images for `cacheMaxAgeSeconds` without rendering them again.
If the manifest expires or the object disappears, prerendering renders it again.
Setting `cacheMaxAgeSeconds` to zero disables reuse.

Runtime buffer cache hits keep their original expiry when publishing.
They do not extend the manifest's lifetime.
Each SSR page checks storage once per distinct image URL.

Image object names contain the SHA-256 hash of their bytes.
Changed bytes get a new URL.
Refreshing a manifest leaves older pages' images available.
Objects have no storage TTL, and the module never deletes them.

Keep objects while any deployed page or cached HTML can reference them.
If you use bucket lifecycle rules, keep objects for that long.

#### Upload headers and failures

Uploads pass content type and immutable cache headers through the driver's `httpMetadata` options.
The R2 binding driver supports these options.
The S3 driver ignores them.
Configure the public bucket or CDN to serve image MIME types and `Cache-Control: public, max-age=31536000, immutable`.

If storage is missing or fails, prerendering keeps the local image URL and static file.
Runtime pages and image responses also keep working through the app.
If publishing succeeds, prerendering skips the local static image file.

### `cacheMaxAgeSeconds`

- Type: `number`{lang="ts"}
- Default: `60 * 60 * 24 * 3`{lang="ts"} (3 days)

Default cache duration in seconds for generated OG images. Controls the internal storage TTL and HTTP `Cache-Control` header duration (`max-age` / `s-maxage`). Can be overridden per image via `defineOgImage`'s `cacheMaxAgeSeconds` option.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    cacheMaxAgeSeconds: 60 * 60 * 24 // 1 day
  }
})
```

See the [Runtime Cache guide](/docs/og-image/guides/runtime-cache) for details.

### `warnMissingSuffix`

- Type: `boolean`{lang="ts"}
- Default: `true`{lang="ts"}

Warn about OG Image components missing the renderer suffix (`.satori.vue`, `.takumi.vue`, `.browser.vue`) in dev mode. Set to `false` to suppress warnings for legacy or test components.

### `includeTwitter`

- Type: `boolean`{lang="ts"}
- Default: `true`{lang="ts"}

Include Twitter card meta tags (`twitter:card`, `twitter:image`, etc) alongside the Open Graph image tags. Set to `false` to only emit `og:image` tags.

When unset, the module respects [`seo.automaticTwitterTags`](https://nuxtseo.com/docs/nuxt-seo-kit/guides/seo-meta) from nuxt-seo-kit before falling back to `true`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  seo: {
    automaticTwitterTags: false
  },
  ogImage: {
    // optional explicit override, takes precedence over seo.automaticTwitterTags
    includeTwitter: false
  }
})
```

### `emojiStrategy`

- Type: `'auto' | 'local' | 'fetch'`{lang="ts"}
- Default: `'fetch'`{lang="ts"}

::deprecated
Deprecated. Runtime always uses Iconify API now. Build-time uses local icons if available. Use `defaults.emojis: false` to disable emoji support entirely.
::

### `browser`

- Type: `BrowserConfig`{lang="ts"}
- Default: `undefined`{lang="ts"}

Set `browser: true` to enable `defineOgImageScreenshot()`{lang="ts"} with automatic local browser selection.
A browser provider object also enables screenshots.
If you omit this option or set it to `false`, screenshot calls throw a setup error.
Component images still select their renderer through the `.browser.vue` suffix.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    browser: true
  }
})
```

Prerender screenshot pages for production. This option does not add browser support to incompatible hosts.

To configure a browser provider, pass an object. For [Cloudflare](https://cloudflare.com) deployments, specify the browser binding name.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    browser: {
      provider: 'cloudflare',
      binding: 'BROWSER'
    }
  }
})
```

See the [Browser Renderer](/docs/og-image/renderers/browser) guide for more details.

### `security`

- Type: `object`{lang="ts"}

Security limits for image generation. See the [Security Guide](/docs/og-image/guides/security) for full details.

- **`secret`**: Signing secret for URL tamper protection. Runtime OG image URLs are signed by default; unsigned requests are rejected with `403`. Leave unset to auto-generate a per-build secret, set an explicit stable string for rolling/multi-instance deploys, or `false` to disable signing. Generate one with `npx nuxt-og-image generate-secret`. See the [Security Guide](/docs/og-image/guides/security#url-signing) for details.
- **`maxDimension`**: Maximum width or height in pixels. Default `2048`.
- **`maxDpr`**: Maximum device pixel ratio (Takumi renderer). Default `2`.
- **`renderTimeout`**: Milliseconds before the render is aborted with a `408` response. Default `15000`.
- **`maxQueryParamSize`**: Maximum query string length (in characters) for runtime requests. Returns `400` when exceeded. Default `null` (no limit).
- **`restrictRuntimeImagesToOrigin`**: Restrict runtime image generation to requests whose `Host` header matches allowed hosts. Default `false`. See the [Security Guide](/docs/og-image/guides/security#restrict-runtime-images-to-origin) for details.
- **`strict`**: Enable strict security mode. Requires `secret`, disables the deprecated `html` option, defaults `maxQueryParamSize` to `2048`, and enables `restrictRuntimeImagesToOrigin`. Default `false`. See the [Security Guide](/docs/og-image/guides/security#strict-mode) for details.

```bash [.env]
NUXT_OG_IMAGE_SECRET=<your-secret>
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    security: {
      strict: true,
    }
  }
})
```

### `debug`

- Type: `boolean`{lang="ts"}
- Default: `false`{lang="ts"}

Enables debug logs and a debug endpoint.
